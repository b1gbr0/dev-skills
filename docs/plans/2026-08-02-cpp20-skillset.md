# Набор скилов по C++20 — срез 1

## Зачем

Готового авторитетного набора скилов по современному C++ не существует
(проверено 2026-08-02: у samber только Go; `crazyguitar/cppcheatsheet` — это
WebFetch-роутер на сайт плюс скил про читаемость; `llnl/smith` — стиль их
собственного проекта; всё остальное в агрегаторах — один и тот же
размноженный `cpp-pro`). Авторитетность в C++ живёт в первоисточниках, а не
в чужих скилах, поэтому набор собирается здесь из них.

Целевой профиль: **C++20 как база, обычный десктопный и сервисный код**. Не
эмбеддед (исключения и RTTI доступны, freestanding не рассматривается), не
HPC/GPU.

Срез 1 — шесть скилов, которые меняют то, что агент пишет на каждом файле.
Продолжение — в разделе Post-Completion, в этот план не входит.

## Базовая линия

Скилы пишутся под компиляторы, у которых C++20 фактически рабочий:
GCC 13+, Clang 17+, MSVC 19.3x+. Apple Clang считать **ограниченной**
площадкой: его библиотечная поддержка C++20 отстаёт, и там, где это влияет
на выбор (`std::format`, ranges, `jthread`), скил обязан назвать
ограничение, а не умолчать о нём.

Если базовая линия неверна — это правится в одном месте, здесь, до запуска.

## Ограничения

1. **Скилы — на английском.** Правило репо (`CLAUDE.md`, `docs/conventions.md`):
   триггеринг зависит от английского `description`. Этот план — на русском,
   он не деливерабл.
2. **Форма — роутер + `references/`.** `SKILL.md` держит то, что нужно
   каждый раз (ориентир 120–180 строк, жёсткий потолок 500); таблицы,
   разборы и длинные примеры уходят в `references/*.md`, каждая ссылка — с
   условием «читать, когда …». Дублирования между телом и references нет.
3. **Ничего не выдумывать.** Правило репо: неверный флаг в скиле агент
   повторяет каждый раз. Любое утверждение про наличие фичи, версию
   компилятора, флаг или имя из stdlib сверяется с первоисточником в момент
   написания — cppreference (в т.ч. страница поддержки компиляторов), C++
   Core Guidelines, документация clang-tidy/clang-format/CMake. Не помнить —
   а проверять.
4. **Граница C++20 / C++23 — обязательная тема.** Под базовой линией C++20
   недоступны `std::expected`, `std::print`, `std::generator`,
   `std::flat_map`, `std::mdspan`, `std::stacktrace`, `views::zip`,
   `views::enumerate`. Скил, который предлагает их как «современный C++»,
   считается сломанным. Там, где фича формально C++20, но библиотечно
   приехала позже (`std::format`, ranges, `jthread`), скил называет
   практическое условие применимости.
5. **Границы между скилами явные.** У каждого `description` — клауза «что
   этот скил НЕ покрывает и куда идти вместо него». Шесть скилов не должны
   срабатывать все разом на один и тот же `.cpp`.
6. **Правило > пример > предотвращаемая ошибка.** Формат тела из
   `docs/conventions.md`: сначала правило, потом минимальный корректный
   пример, потом failure mode. Императив, не «consider».
7. **Каждый скил — 3–5 evals**, и `trap` пишется первым. Если конкретную
   ошибку модели без скила назвать нельзя — раздел или скил лишний.
8. **Существующий `cpp-russian` не трогать.** Он про язык изложения, не про
   написание кода; пересечений быть не должно.

## Приёмка

- `python3 scripts/validate.py` — 7 skill(s), 0 errors, 0 warnings.
- `shellcheck scripts/*.sh` — чисто (это второй шаг CI).
- Ни в одном `SKILL.md` тело не длиннее 500 строк.
- Каждый `description` ≤ 1024 символов (мерить `wc -m`, не `wc -c`).
- Grep по всем шести скилам не находит `std::expected`, `std::print`,
  `std::generator`, `std::mdspan`, `std::flat_map` иначе как в явном
  контексте «это C++23, под нашей базой недоступно».
- Коммиты — Conventional Commits со скоупом по скилу
  (`feat(cpp-build): add preset section`), по коммиту на скил.
