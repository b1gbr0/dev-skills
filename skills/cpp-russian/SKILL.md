# C++ по-русски

Скилл о том, **как говорить и писать о C++ по-русски**: какие термины использовать, что переводить, что оставлять латиницей и как встраивать латиницу в русскую фразу. Он не касается того, как писать код на C++.

Проблема, которую он решает: при переходе на русский язык легко начать переводить всё подряд — включая то, что переводу не подлежит. Получается текст, который выглядит русским, но не опознаётся собеседником: он не может сопоставить услышанное с тем, что видит в исходнике.

## Главное правило: идентификатор — не слово, а имя

Всё, что можно скопировать в исходный файл, в русском тексте **остаётся неизменным**: ключевые слова, имена типов и функций, флаги компилятора, тексты диагностик.

```
✗ Здесь лучше использовать карту вместо вектора.
✓ Здесь лучше использовать std::map вместо std::vector.
✓ Здесь лучше взять словарь std::map вместо вектора std::vector.
```

Почему это критично, а не вопрос вкуса: русское слово-перевод сталкивается с **предметной лексикой проекта**. Во фразе «в этом месте мы кладём точку в карту» слово «карта» в проекте про навигацию, картографию или игровые уровни неотличимо от доменной сущности. Собеседник будет искать в коде класс `Map` предметной области, не найдёт и потеряет время. Идентификатор `std::map` такой двусмысленности не создаёт никогда.

**Если перевод термина может быть прочитан как предметный термин проекта — используй идентификатор.** Это правило сильнее стремления к красивому русскому тексту.

## Три допустимые формы термина

| Форма | Когда | Примеры |
|---|---|---|
| Перевод | Есть устоявшийся русский эквивалент | pointer → указатель, inheritance → наследование, lifetime → время жизни |
| Транслитерация | Заимствование уже вошло в русский технический язык | mutex → мьютекс, iterator → итератор, template instantiation → инстанцирование |
| Латиница | Устоявшегося эквивалента нет | SFINAE, RAII, CRTP, ODR, rvalue, lock-free |

Четвёртой формы — **сочинить свой перевод** — не существует. Если термин не попадает ни в одну из трёх категорий, оставь латиницу. Непереведённый термин собеседник опознает и при необходимости найдёт; выдуманный — не опознает никогда.

## Никогда не переводится

- **Ключевые слова и спецификаторы**: `const`, `constexpr`, `noexcept`, `override`, `virtual`, `co_await`, `requires`.
- **Идентификаторы стандартной библиотеки**: `std::map`, `std::vector`, `std::move`, `std::optional` — целиком, вместе с `::`, `<>` и `()`.
- **Идентификаторы из кода проекта**: имена классов, функций, файлов, пространств имён.
- **Флаги и опции**: `-Wall`, `-fsanitize=address`, `/W4`, `-std=c++20`.
- **Тексты диагностик компилятора**: сообщение об ошибке цитируется дословно на английском, комментарий к нему — по-русски.
- **Названия стандартов**: C++11, C++17, C++20, C++23.

## Как склонять латиницу

Латинский идентификатор не склоняется. Грамматику несёт **русское существительное-носитель**, поставленное рядом: функция, тип, класс, шаблон, контейнер, ключевое слово, идиома, оператор.

```
✗ в мапе, во vector'е, замувить, сделать мув, отнаследоваться от Base
✓ в словаре std::map, в контейнере std::vector, переместить (std::move)
✓ функция std::move() возвращает…, у шаблона std::function<> есть…
✓ класс наследуется от Base
```

Для гибридов через дефис латинская часть заморожена, склоняется русская: «rvalue-ссылка → rvalue-ссылки → rvalue-ссылкой», «лямбда-выражение → лямбда-выражения». Допустим и обратный порядок: «ссылка rvalue».

Транслитерации, вошедшие в язык, склоняются как обычные русские слова: «мьютекса», «итератору», «концептов», «функторами», «в векторе».

## Первое упоминание — с оригиналом в скобках

Когда термин переведён, при первом появлении в тексте дай английский оригинал:

```
✓ конструктор перемещения (move constructor) забирает ресурсы временного объекта
✓ идиома RAII (resource acquisition is initialization)
✓ представление (view) не владеет элементами
```

Дальше по тексту — только русский вариант. Это позволяет собеседнику сопоставить термин с документацией и не гадать, о чём речь.

## Разговор с русскоязычным собеседником

1. **Называй сущности так, как они называются в коде.** Пользователь читает исходник, а не перевод: он ищет глазами `std::map`, а не «карту».
2. **Не защищай выдуманный термин.** Если собеседник переспрашивает, что означает употреблённое слово, — это сигнал, что перевод не опознан. Правильная реакция: назвать исходный идентификатор («речь про `std::map` — ассоциативный контейнер из стандартной библиотеки»), а не объяснять придуманное слово.
3. **При неоднозначности идентификатор идёт первым, пояснение вторым**: «`std::span` — невладеющее представление непрерывного участка памяти», а не наоборот.
4. **Не переводи сообщения об ошибках.** Цитируй диагностику дословно и объясняй по-русски — иначе её нельзя найти поиском.
5. **Регистр — нейтрально-деловой.** Без канцелярита и без панибратства. Обращение на «вы», если собеседник не задал другой тон.

## Комментарии и документация

- **Проза — по-русски, код — по-английски.** Идентификаторы в коде остаются английскими, даже если весь комментарий русский. Русские имена переменных и функций не создаём.
- **Теги doxygen — латиницей** (`@param`, `@return`, `@throws`), описания при них — по-русски.
- **Имена параметров в тексте комментария** пишутся как в сигнатуре, не переводятся и не склоняются.
- **Комментарий объясняет «почему», а не «что»** — это общее правило, но по-русски особенно заметно, когда комментарий пересказывает код словами.

```cpp
/// Отправляет накопленные события в очередь публикации.
///
/// @param batch  пакет событий; должен быть непустым
/// @param policy стратегия повторов при отказе транспорта
/// @return       количество принятых событий
/// @throws std::system_error при недоступности транспорта
///
/// Вызов блокирующий: ждёт освобождения места в очереди. Для неблокирующего
/// поведения используйте try_publish().
```

## Если устоявшегося перевода нет

Скажи это прямо и оставь латиницу:

```
✓ Это лечится через CRTP — устоявшегося русского названия у идиомы нет.
✓ Здесь срабатывает SFINAE: неудачная подстановка убирает перегрузку из
  списка кандидатов, а не превращается в ошибку компиляции.
```

Расшифровка акронима — не имя механизма. «Ошибка подстановки не является ошибкой» объясняет, что значит SFINAE, но не может использоваться как название: собеседник не сопоставит эту фразу ни с одним источником.

## Проверка перед отправкой

- Каждое русское слово, обозначающее сущность из stdlib, заменено на идентификатор или сопровождено им.
- Ни один латинский идентификатор не просклонён и не получил русских окончаний.
- Переведённые термины при первом упоминании снабжены оригиналом в скобках.
- Ни один термин не переведён «по смыслу» в обход глоссария.
- Сообщения компилятора не переведены.
